01

핵심 기능 — 하단 탭 4개

화면마다 질문이나 행동 하나만 두고, 480px 모바일 한 줄 구성에 하단 탭 4개(홈·원가·장부·더보기)로 정리했습니다.

홈오늘 챙길 것만 모아서

아직 안 한 것만 카드로 보여 주고, 다 했으면 아무것도 나오지 않습니다.

  • 오늘 할 일 카드 · 이번 달 남은 돈
  • 원가율 높은 메뉴 TOP3와 "30%로 맞추려면 얼마" 안내
  • 답글 안 단 리뷰 · 발주할 품목 · 다가오는 날짜(D-day)

원가재료값 → 메뉴 원가율 → 적정 판매가

  • 재료 g당 단가 계산, 메뉴 등록·편집, 반제품 지원
  • 원가율을 색으로 표시: 30% 이하 초록 · 38% 이하 노랑 · 초과 빨강
  • 예시 데이터로 먼저 체험해 볼 수 있음

장부명세서 · 재고 · 월 정산

  • 거래명세서 입력과 가격 이상 경고
  • 재고·발주서 작성 — 발주서를 복사하거나 문자로 보내기
  • 월 정산: 매출과 비용을 넣으면 남은 돈과 경고가 나옴, 거래처별 매입 집계
  • 정산표 내려받기

더보기지원금 · 리뷰 · 날짜 알림

  • 지원금 찾기: 질문 7개에 답하면 약 25개 제도 중 해당하는 것을 부합도(추정)와 함께 보여 주고, 신청 순서까지 정리
  • 리뷰 답글 초안: 직접 기록한 리뷰에 별점 구간(4~5점 · 3점 · 1~2점)별 초안 2개를 가게 이름·작성자 이름으로 생성해 복사, 스마트플레이스에 붙여 넣어 등록
  • 답글 완료는 사장님이 직접 표시, 신청·납부 날짜 알림, 내 데이터 내려받기·삭제
02

계산 · 판정 규칙

g당 단가

포장 가격 ÷ (포장 무게 × (1 − 버리는 비율 ÷ 100))

원가율 색

30% 이하 초록 · 38% 이하 노랑 · 초과 빨강

적정 판매가

원가 ÷ 0.30 을 100원 단위로 올림

계산·판정 규칙은 14가지로 정리해 기능 명세서에 화면 ID별 입력·처리·출력·예외와 함께 적었습니다.

03

보안 · 구조

브라우저는 앱 서버를 거쳐서만 데이터베이스에 접근합니다. 브라우저 → Next.js 서버 라우트(/api/auth · /api/db · /api/rpc) → MySQL 8.4.

구분내용
인증비밀번호 scrypt 해시, 세션 쿠키 30일, 같은 IP·이메일 5회 실패 시 15분 제한
접근 제어허용된 표·열만, 내 가게 데이터만, id·store_id·시각은 서버 전용 (값은 항상 ?로 바인딩)
외부 연동스마트플레이스 주소는 naver.com·naver.me만 허용, 네이버 로그인 정보는 수집하지 않음
실행Docker Compose(app + mysql), 데이터는 볼륨에 보관
규모API 5개(인증 3 · 데이터 1 · 함수 1), DB 표 14개, 단위·DB 테스트 67개 통과
04

5일 개발 단계

단계내용
1MySQL 전환 · 로그인 (Supabase에서 이전, 세션, Docker 구성)
2원가 · 장부 · 정산 (원가 계산, 명세서, 재고·발주, 월 정산, 경고·내려받기)
3지원금 매칭 (약 25개 제도, 질문 7개, 부합도 추정, 날짜 알림)
4가게 등록 · 리뷰 (가게 정보, 스마트플레이스 주소, 리뷰 기록, 답글 초안)
54탭 정리 · 전체 점검 (탭 8개 → 4개, 모든 화면 점검)

화면 점검

홈·원가·장부·더보기의 모든 버튼·입력·이동·삭제·내려받기·저장 후 새로고침 확인.

더미 데이터 검증

리뷰 70개 · 명세서 45건 · 재료 60개로 검색·더 보기 확인.

05

한계 · 향후 계획

현재 미구현내용
입력·화면거래명세서 수정(현재는 삭제 후 재입력), 금액 천 단위 쉼표, 재고 "개" 단위
운영비밀번호 재설정 메일, 자동 백업, 외부 공개 호스팅
데이터지원금 금액·조건을 공식 공고 기준으로 정기 갱신 (현재는 블로그·뉴스 요약 기반)
확장명세서 사진 인식, 네이버가 공식 연동을 열면 리뷰 자동 수집

지원금 금액·조건은 신청 전 공식 공고로 확인해야 하고, 부합도(%)는 추정치입니다.
